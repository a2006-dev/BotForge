# BotForge 信息架构（IA）

> 交付物 2/3（对应《BotForge UI/交互 提示词》§15）
> 本文档描述页面层级、导航关系、每个页面的信息职责与数据来源。
> 参数标注：`[已实现]` 后端与 UI 均在仓库中；`[待补齐]` 后端已有/UI 缺；`[空壳]` 后端缺失，本期只做 UI 框架。

---

## 1. 产品定位

BotForge 是「**机器人运行管理中心**」，不是配置面板集合。

三条设计主线：

1. **看得见** — 一眼得知机器人是否在跑、跑了多久、最近是否异常
2. **管得住** — 权限、插件、工具、危险操作有明确闸门与确认
3. **查得清** — 任何一次异常、任何一次危险调用都能回溯到时间和触发者

对比现状：当前首页偏「统计 + 入口」，信息层级以「数据卡片」为先；新架构以「**运行状态**」为先。

## 3. 首页 Dashboard

**职责**：回答三个问题 —— 现在正常吗？出过什么问题？下一步该做什么？

信息顺序（自上而下，**顺序即优先级**）：

| 区块 | 内容 | 显示条件 | 数据源 |
|---|---|---|---|
| ① StatusHero | 巨型状态文字 + 运行时长 + 最近消息时间 + 今日断线次数 | 常驻 | `BotStatusRegistry` 推送 |
| ② 主操作按钮 | 启动 / 停止（唯一主操作） | 常驻 | `BotService` |
| ③ AttentionCard | 异常聚合：权限缺失、登录失效、连续断线 ≥ 3 次 | **无问题时整块不渲染** | `PermissionGuide` + `BotManager` |
| ④ 机器人概览 | 每个机器人一行：昵称 + 状态 Pill + 最近消息相对时间 | 有机器人时 | `repo.personas()` |
| ⑤ 最近事件 | 最多 6 条，含时间戳与级别色 | 常驻（空态给引导） | `Logger.listener` 推送 |
| ⑥ 快捷入口 | 查看全部日志 / 插件 / 试聊 | 常驻 | — |

**明确移除**：现有首页的「数据」统计区（机器人/插件/日志三个数字）在新架构中**移到各自 Tab**，首页只保留「日志总数」作为事件区的尾随说明。理由：统计数字对「要不要启动」无决策价值，却占据首屏高度。

**空态规则**：
- 未启动 → StatusHero 显示「离线」，② 变「启动服务」，④⑤ 显示引导文案而非空表格
- 已启动无事件 → 事件区显示「运行正常，暂无事件」
- 有异常 → ③ 置顶于 ④ 之上（异常优先于概览）

## 4. 机器人 Tab

**职责**：机器人群体的管理，单机器人进入详情。

```
Bots
├── 列表（卡片式）
│   └── 卡片字段：昵称 / AppID / 状态 Pill / 当前连接代数 / 最近心跳间隔 / 最近消息时间
└── 详情 BotDetail
    ├── 状态区（同 StatusHero，缩小版）
    ├── 连接信息：心跳间隔（服务端下发值）/ 连接代数 / 重连次数
    ├── 配置：人设、模型、触发方式
    ├── 行为：试聊入口
    └── 危险区：删除机器人（L3）
```

## 5. 能力 Tab Capabilities

**职责**：所有「机器人能做什么」的统一入口。当前散落在设置页，收敛到此。

```
Capabilities

├── 记忆         → Memory         [待补齐]

    └── 时间轴：危险操作 + 触发者 + 结果 + 可展开参数
```

## 6. 设置 Tab

按「影响范围」分组，不按实现模块分组。

| 分组 | 项目 |
|---|---|
| 连接 | 网关地址、密钥（`SecretStore`）、心跳策略 |
| 运行 | 开机自启、**自动拉起服务**、后台保活 |
| 安全 | 权限中心入口 [空壳]、白名单用户/群、危险操作确认级别 |
| 外观 | 主题（跟随系统 / 亮 / 暗）、字号缩放 |
| 关于 | 版本、日志导出、开源许可 |

> 「自动拉起服务」是已落地开关（`Config.autoRestart`），文档中的描述与实现一致。

## 7. 数据流（单向）

```
      BotService / Logger / BotStatusRegistry      ← 真实状态源
                     │
                     │ push（listener / Flow）
                     ▼
              DashboardStore (StateFlow)
                     │
                     │ collectAsState
                     ▼
                 Compose UI
```

规则：

1. **UI 不直接读 Service 或 Repository**，只读 Store 暴露的 StateFlow
2. **推送优先**：`Logger.listener`、`BotStatusRegistry.listener` 是主路径
3. **轮询仅兜底**：`refreshStatic()` 15 秒一次，仅补偿推送遗漏（因为对象存储、模型列表没有推送源）
4. 任何写操作走 Store 的意图方法，不直接调 Repository

> 这条规则即任务书「使用 StateFlow 实现合理的状态同步」的落地形式，已实现并推送（`84fb74c4`）。

## 8. 导航与返回规则

- 二级页统一左上返回箭头，**无底部导航**
- 从首页「查看全部日志」进入 Logs 时，返回回到首页，不跳 Tab
- 危险操作确认用 ModalBottomSheet，**不跳新页**
- 首次引导仅在「无任何机器人且从未启动过」时出现，可跳过
- 深链：通知栏点击 → 直达 StatusHero 所在 Tab（首页），不弹新页

## 10. 与提示词的差异说明

提示词 §6 列出的页面中，以下**本期只能做空壳**，原因已在 §0 现状校正中说明：

- **权限中心**：缺 L1~L4 风险分级后端
- **审计日志**：缺审计写入后端（现只有滚动日志，无结构化留档）
- **主人绑定**：缺 owner 概念，`/allow` 白名单为空时任何人可首注册

这三项的 UI 会完整实现结构与交互，数据区显示「功能未启用」的明确说明，**不伪造数据**。
