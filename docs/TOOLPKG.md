# 工具包规范

本文定义 BotForge 工具包的目录结构、清单位段、执行协议与分发格式。

规范版本：`api = 1`

---

## 1. 这是什么

工具包是一段在 BotForge 内置 Linux 环境里运行的脚本，加上一份描述它的清单。

应用负责三件事：按清单生成参数表单、收集参数、执行入口脚本并把标准输出显示出来。
脚本负责实际的业务逻辑。

工具包不是插件。插件（`plugin/` 目录下的 dex）运行在应用进程里，能调用应用内部接口；
工具包在独立的 Linux 进程里运行，只能通过环境变量接收输入、通过标准输出返回结果。
两者的隔离强度和能力边界完全不同，不应混淆。

---

## 2. 目录结构

```
plugins/
└── system-info/          ← 目录名即工具包 id，建议与清单中的 id 一致
    ├── tool.json         ← 清单元文件，必需
    ├── run.sh            ← 入口脚本，文件名由清单的 entry 字段指定
    └── ...               ← 其余文件随意，脚本可用相对路径引用
```

工具包根目录位于应用外部存储：

```
/sdcard/Android/data/com.ajx.botforge/files/plugins/
```

在容器内，同一目录的可见路径是：

```
/sdcard/Android/data/com.ajx.botforge/files/plugins/
```

`/sdcard` 在容器内被绑定到宿主机的 `/storage/emulated/0`，因此上面两条路径等价。

## 3. 清单字段

`tool.json` 为 UTF-8 编码的 JSON 对象。

### 3.1 必需字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 工具包标识。仅用于界面展示与结果隔离，不做文件名约束 |
| `name` | string | 显示名称 |
| `entry` | string | 入口脚本文件名，相对于工具包目录 |

### 3.2 可选字段

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `version` | string | `0.0.0` | 语义化版本 |
| `description` | string | 空 | 一句话说明用途，显示在列表里 |
| `author` | string | 空 | 作者名。为空时界面显示「未标注」 |
| `homepage` | string | 空 | 项目主页，为将来的远程索引预留 |
| `license` | string | 空 | 许可证标识，建议用 SPDX 短名，如 `Apache-2.0` |
| `api` | int | `1` | 清单格式版本。高于应用支持的版本时不予加载 |
| `timeoutSec` | int | `60` | 超时秒数。超时后强制结束进程，输出保留已捕获部分 |
| `risky` | bool | `false` | 高风险标记。为真时列表显示红色「高风险」标签 |
| `params` | array | 空 | 参数定义数组，见下节 |

### 3.3 参数定义

`params` 中每一项是一个对象：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 参数名，仅允许 `[A-Za-z0-9_]`，用于拼接环境变量名 |
| `label` | string | 表单上显示的标签。缺省时用 `name` |
| `type` | string | 输入类型，当前支持 `text` |
| `default` | string | 默认值 |
| `required` | bool | 是否必填。当前版本不做强制校验，由脚本自行判断 |
| `hint` | string | 输入框占位文字与说明文字 |
| `options` | array | 可选项列表，为将来的下拉框预留 |

> `required` 与 `options` 在当前版本尚未参与界面逻辑。写入这两个字段不会报错，
> 但不会有额外效果。有意在后续版本中启用。

## 4. 执行协议

### 4.1 输入

参数以环境变量形式注入，变量名为 `BF_PARAM_` 加参数名：

```
BF_PARAM_target=example.com
BF_PARAM_count=10
```

脚本用 `$BF_PARAM_target` 读取即可。

参数值经单引号包裹并转义，因此可以安全包含空格、引号、`$` 等字符——
脚本拿到的就是用户输入的原文。

### 4.2 工作目录与执行方式

工作目录被设为工具包目录本身，因此脚本可以直接写 `./data.txt` 访问同目录文件。

入口脚本以 `sh <entry>` 执行，不要求可执行位。因此压缩包分发时不必保留权限位。

### 4.3 输出

标准输出与标准错误合并，作为结果文本显示。

退出码 `0` 表示成功，非零表示失败。界面按退出码着色，非零时显示为红色。

超时会强制结束进程，已捕获的输出保留，同时附带「执行超时」。

### 4.4 环境

脚本运行在 Alpine Linux 容器内，可用的东西取决于用户是否安装了对应软件包。

容器内默认可用：`sh`、`busybox` 提供的常用工具（`ls`、`cat`、`grep`、`sed`、`awk`、
`df`、`ps`、`wget` 等）。

若脚本依赖 `curl`、`git`、`python3`、`node` 等，应在 `description` 中写明所需的软件包，
并在脚本开头做可用性检查：

```sh
command -v curl >/dev/null 2>&1 || {
    echo "需要 curl，请先在终端中执行 apk add curl"
    exit 1
}
```

不要假设用户已安装任何额外软件包。这样做会让工具包在别人的设备上莫名其妙地失败。

## 5. 完整示例

`tool.json`：

```json
{
  "id": "http-head",
  "name": "HTTP 头查询",
  "version": "1.0.0",
  "description": "读取指定 URL 的响应头，需要容器内已安装 curl",
  "entry": "run.sh",
  "author": "example",
  "license": "Apache-2.0",
  "api": 1,
  "timeoutSec": 20,
  "params": [
    {
      "name": "url",
      "label": "目标地址",
      "type": "text",
      "default": "https://example.com",
      "hint": "含协议头的完整地址"
    }
  ]
}
```

`run.sh`：

```sh
#!/bin/sh
# 读取目标地址的响应头。参数由应用以环境变量注入。

URL="$BF_PARAM_url"

if [ -z "$URL" ]; then
    echo "目标地址为空"
    exit 1
fi

command -v curl >/dev/null 2>&1 || {
    echo "需要 curl，请先在终端中执行 apk add curl"
    exit 1
}

curl -sSI --max-time 10 "$URL"
```

## 6. 安全边界

这一点必须说清楚，因为它决定了工具包分发的信任模型。

**工具包脚本以 BotForge 应用自身的权限运行。**

具体含义：

- 能读写 `/sdcard` 下任意文件，包括照片、文档、其他应用的共享数据；
- 能读写 BotForge 的私有目录，包括数据库与已保存的配置；
- 能访问网络，没有域名白名单；
- 能创建后台进程，进程在工具包执行结束后不一定会被清理。

**应用不做沙箱隔离。** 没有 seccomp 过滤，没有独立 uid，没有文件系统只读约束。

`risky` 字段只影响界面是否显示一个红色标签，不改变任何实际权限。它是一个提示，
不是一道防线。

因此分发工具包时的责任在分发者：不要分发来源不明或行为不透明的工具包。

## 7. 分发格式

单文件分发时使用 `.bfpack` 扩展名。

`.bfpack` 就是一个标准 tar 归档（不压缩），解包后得到工具包目录：

```
tar cf http-head.bfpack -C plugins http-head
```

安装方式是把解包结果放到 `plugins/` 下。当前的版本尚未实现一键导入，
需要用户手动放置或通过终端解包。

清单中的 `homepage` 与 `author` 字段为此后的中心化索引预留：届时应用可以从
索引读取清单、展示工具包信息、校验下载来源。这些字段现在就该填好，
不要等到那时候再补。

---

## 8. 版本演进

`api` 字段用于处理格式演进。

应用当前支持 `api <= 1`。清单中的 `api` 高于应用支持的版本时，该工具包不予加载，
界面上不会出现——这是刻意选择：静默跳过比按未知格式解析再执行更安全。

新增可选字段不提升版本号；改动已有字段的语义、或新增必需字段，才提升版本号。
